> 2026-11-12 22:29–22:32（+08:00），本书对 12 个 URL 做了双客户端实测：Python `urllib` 与 `curl`，同一桌面 UA，同一正文提取口径（去 script/style → 去标签 → HTML 实体解码 → 去全部空白）。

1. **第 18 章《翻译的失真》需要一手证据，而不是修辞。** 「原始出处打不开，二手转引就成了唯一可得的事实」这句话，此前只有零散 anecdote。本卡把它变成**带脚本、带原始输出、带 MD5 的可复现测量**。

### 一处必须精确表述的「一致」：szns 转载件

| 观测 | 结果 |
|---|---|
| 字节数（三次抓取） | **87,054 / 87,054 / 87,054 —— 相同** |
| 原始 HTML MD5（三次） | `3849196a…`（入库存档）/ `4d6b5676…`（交叉核对）/ `cc365c4e…`（复核重抓）—— **三次都不同** |
| 差异位置 | 仅一段**等长的会话 token**（偏移 ~1754–1794）与一个**时间戳**（`14…8` → `22…5`，偏移 ~6117） |
| **去标签后正文** | **5,146 字，逐字全等** |

🔑 **裁决**：
- ✅ 可以说「**正文与存档逐字全等**」。
- ❌ **不可以说「与存档字节全等」或「MD5 一致」**。本书第二轮曾据字节数相同写下「与已入库存档一致」，**属过度声称，已更正**。
- 🔑 **原始 HTML 的 MD5 不是页面身份的稳定指纹**（动态 token / 时间戳会改它而不改长度）。**存档完整性须比对提取后的正文，同时记录两者。**

> ⚠️ 这与本轮另一条教训同源：0005 建卡时记「15,791 字节」，复核得 15,392 字节，差 399 字节而原脚本未留存。**一个无法复现的字节数，不是证据，是印象。**

## 测量工具自身的两处缺陷（已公开修正）

本书要求别人可复现，就必须交出工具自己的错误。

**缺陷一：v1 判决口径把三件不同的事混为一谈**

v1 把 `404 / 403 / 412 / 传输失败` **一律记为 `dead`**。
- 「内容已删除」（404）是**关于世界**的断言；
- 「本客户端被拒绝」（403/412）只是**关于本次测量**的断言；
- 「本机本时段连不上」（http=0）连测量都不完整。

**混为一谈会制造本书正在批评的那种失真**：把访问控制误诊成信息消亡。
→ v2 拆为 `gone` / `blocked` / `unreachable`。**v1 原判保留在 `verdict` / `verdict_v1` 字段，未静默改写历史测量**；v2 由已记录的 HTTP 码与正文长度确定性推导，**未重新抓取**。

**缺陷二：v2 首次回填时漏传 `marks`，制造了新的失真**

回填脚本对交叉核对记录传入空 `marks`，导致**搜狐 `soft404` 与百度知道 `ai_flagged` 被误降为 `ok`**（6 处）。已修正并写入 JSON 的 `instrument_caveats`。
🔑 **口径升级本身也要复核，否则「修正」会制造新的失真。**

**另有两处口径注意事项（已写入脚本与 JSON）**

1. **`urllib` 在 `HTTPError` 分支不读响应体** → `bytes=0` **不代表响应为空，只代表未读体**。实测 gov.cn 404：urllib 记 0 B，curl 记 15,556 B / 493 字（那是 404 错误页本身）。**跨客户端比字节数前，必须确认两侧都读了体。** v2 已补读体。
2. **同一活页在两个客户端间也有字节差**：百度知道 urllib 154,628 B / 1,050 字 vs curl 154,619 B / 1,047 字（差 9 B / 3 字，动态内容）。→ **字节数不能当作页面身份的指纹，除非内容静态。**

## 反方与局限

1. 🚨 **最强反对：这是一份按结果挑出来的样本，不能用来估计发生率。**
   12 个 URL 是**本书自己的引用清单**，其中 7 个在第二轮就已被记为「疑似不可达」。**「7/8 不可引证」在很大程度上是对既有怀疑的再确认，不是独立证据。**
   → **本卡只能支撑「这 7 条具体引用在本次测量中不可用」，不能支撑「中文健康信息正在系统性腐烂」。** 后者需要**随机抽样或分层抽样**，本卡没有。
   → **第 18 章若要用「系统性消失」这个说法，必须另做抽样，或把措辞降为「本书引用的这批来源中」。**

2. 🚫 **`blocked` ≠ `gone`。** nhc / nmpa 的 412、知乎的 403 **只说明本客户端被拒**。412 常见于政务站 WAF 要求 JS 置 cookie；403 可能是反爬。**这些页面的内容很可能完好存在**，换浏览器就能看。**不得写成「政府数据已删除」。**

3. 🚫 **`unreachable` ≠ 服务宕机。** archive.org 两个客户端失败模式不同（urllib 3× SSL EOF / curl 28 超时），**只能断言本机本时段不可达**。不得断言该服务全局故障，也不得据此说「存档服务不可用」。**本书全部 archive.org 快照仍标「待建」，原因是本次不可达，不是该服务不存在。**

4. 🚫 **`js_shell` 是客户端能力边界，不是内容缺失。** 头条 0 字正文很可能是 JS 渲染 + 反爬。**用带 JS 的浏览器可能取得全文。** 本卡不声称「头条文章已消失」。

5. 🚫 **单一时点、单一网络位置、单一 UA。** 全部测量在 2026-11-12 22:29–22:32（+08:00）、同一台 macOS、同一桌面 UA 下完成。**未做跨时段、跨网络、跨 UA 复测。** 链路状态是时间的函数，**本卡数字的有效期就是那个时间戳**。

6. 🚫 **12 个目标不是随机样本，也不是分层样本**，且**主机高度集中**（11 个主机里 3 个是政务站、2 个是搜狐）。**不得外推到「中文互联网」整体。**

7. 🚫 **`ai_flagged` 不构成任何内容判定。** 百度知道被标 `ai_flagged` **仅因 HTML 含 `ai_detect` 字段**；实测 `ai_score`=0.00016993、`pre_label`="0"，全页「AI生成」类声明命中 0。**原推断「疑批量生产」已推翻**（第 10 处推翻，见 [claim-0030](claim-0030-diet-exercise-ratio.md)）。**本卡的 `ai_flagged` 标签不得被下游读成「该来源是 AI 生成的」。**

8. 🚫 **本卡不测量内容质量，只测量可达性。** 「可引证」= HTTP 200 且正文 ≥200 字，**不等于「内容正确」「来源权威」**。百度知道是唯一可引证的一条，**但它是 UGC、无资质、20.6 万条高产量账号，D 级限定不变**。

9. ⚠️ **D 级定级本身待裁决。** 本书 D 级原定义为「访谈 / 田野」，本卡是作者技术实测。**归类为 D 并注明子类是临时处理，须人工确认**；若认为应另设级别，本卡须改级。**不自行修改 EDITORIAL 定义。**

10. ⚠️ **脚本与 JSON 的 MD5 会随后续编辑变化。** 本卡「存档完整性」表是入库时快照，**以 git 历史为准**。
