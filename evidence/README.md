# 证据层

> 本书主张"信任崩塌源于验证机制缺失"。这一层就是本书自己的验证机制。
> **规则：没有卡的数字不进正文。**

## 目录

| 目录 | 内容 | 许可 |
|---|---|---|
| `claims/` | 每条关键论断一张卡：说法、证据、分级、反方、核查日期 | CC BY-NC-SA 4.0 |
| `data/` | 原始数据 CSV/JSON，附来源与采集日期 | CC0 |
| `scripts/` | 可复现脚本（采集、清洗、统计、图表） | MIT |
| `interviews/` | 访谈提纲、知情同意模板、**脱敏后**转录 | CC BY-NC-SA 4.0 |

`interviews/raw/` 存放原始录音与未脱敏转录，**已被 .gitignore 排除，永不入库**。

## 证据分级

| 级 | 类型 | 使用规则 |
|---|---|---|
| A | 系统综述、Meta 分析、RCT、权威临床指南 | 可直接支撑断言 |
| B | 队列、观察性、机制研究 | 需注明局限（相关≠因果） |
| C | 行业报告、财报、监管文件、司法文书、政策文本 | 注明发布方与利益相关 |
| D | 访谈、田野观察、公开内容采样 | 不可外推为普遍结论 |
| E | 作者经验、推断、假设 | **必须显式标注**，不得伪装成证据 |

完整规范见 [../EDITORIAL.md](../EDITORIAL.md)。

## 怎么新增一张卡

1. 复制 [claims/TEMPLATE.md](claims/TEMPLATE.md)
2. 命名 `claim-NNNN-短-slug.md`，编号递增
3. 填写：论断原文、分级、来源（含 URL/DOI + 采集日期 + 存档）、原文关键句、反方意见、利益相关
4. 状态标 `待核实`，核查通过后改 `已核实`
5. 在正文里链接这张卡，并把卡 id 写进章节 frontmatter 的 `claims` 字段

## 卡的状态

- `待核实` — 有线索，尚未找到可靠来源。**正文中不得作为已确立事实使用**
- `已核实` — 来源可靠，已交叉验证
- `有争议` — 证据冲突，正文需并列呈现
- `已推翻` — 原论断错误。**不删除**，保留原文与推翻理由

推翻一张卡是本书的成就，不是失败。修订史本身就是论点。

## 数据规范

每个数据文件配一个同名 `.meta.md`：

```
- 文件名：
- 来源：
- 发布方：
- 采集日期：
- 采集方式：（手工 / 脚本路径）
- 许可：
- 字段说明：
- 已知局限：
- 利益相关：
```

## 脚本规范

- Python 3，依赖写进 `requirements.txt`
- 每个脚本顶部注明：用途、输入、输出、运行方式
- 不做网络采集时绕过平台条款的事；采集脚本需注明目标与频率限制
- 输出写入 `data/`，不覆盖原始数据
